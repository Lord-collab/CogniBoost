1. ОБЩЕЕ ОПИСАНИЕ
--------------------------------------------------------------------------------
CogniBoost — мобильное приложение (Android/iOS/Windows) для тренировки
когнитивных навыков: памяти, внимания, логики, языка и скорости реакции.
Включает 14 мини-игр, 5 IQ-тестов, систему баллов, 24 достижения,
ежедневные стрики и облачную синхронизацию.

Технологии:
  - .NET MAUI (кросс-платформенный UI)
  - C# 13
  - SQLite (sqlite-net-pcl) — локальная БД
  - Supabase (PostgreSQL + REST API) — облачное хранилище
  - Plugin.LocalNotification — локальные уведомления
  - XAML + AppThemeBinding — тёмная/светлая тема


2. АРХИТЕКТУРА (MULTI-LAYER)
--------------------------------------------------------------------------------
Проект разделён на три слоя:

  2.1. Models/ — Модели данных
  ─────────────────────────────
  7 файлов:

    BrainSkill.cs        — перечисление когнитивных навыков (Memory, Focus,
                           Language, Logic, Speed)
    GameDefinition.cs    — описание игры: ID, название, описание, навык,
                           эмодзи, фабрика страницы, цена разблокировки
    GameResult.cs        — результат игровой сессии (score, maxScore,
                           earnedPoints, skill, time)
    SqliteEntities.cs    — сущности SQLite: UserEntity, GameResultEntity,
                           TestResultEntity, SettingEntity (см. раздел 3)
    TestQuestion.cs      — вопрос теста: текст, варианты ответа,
                           правильный индекс
    TestResult.cs        — результат IQ-теста (correct, total, iqScore)
    UserProfile.cs       — профиль пользователя для UI (имя, возраст,
                           аватар, навыки)

  2.2. Services/ — Бизнес-логика (24 файла)
  ──────────────────────────────────────────
  Сгруппированы по назначению:

  —──────── Авторизация и профиль ─────────
    AccountStore.cs       — фасад: проверка входа/гостя, чтение имени
    AuthService.cs        — регистрация, вход, хеширование SHA-256 + соль,
                            миграция гостя в полноценный аккаунт
    UserDataService.cs    — CRUD профиля, навыки, аватар, сброс прогресса

  —──────── Хранение данных ───────────────
    DatabaseService.cs    — инициализация SQLite, создание таблиц,
                            миграция из Preferences (старая версия)
    ProgressStore.cs      — чтение/запись истории игр и тестов, расчёт
                            баллов навыков и общего балла мозга
    SupabaseConfig.cs     — URL + anon key Supabase

  —──────── Геймификация ──────────────────
    PointsService.cs      — начисление (10–65 за игру), трата, баланс
    StreakService.cs      — ежедневные стрики, бонус за серию
    AchievementsService.cs— 24 достижения, проверка условий, разблокировка
    UnlockService.cs      — покупка игр за баллы, кеш разблокированных

  —──────── Облако ────────────────────────
    CloudApiService.cs    — REST-клиент Supabase (CRUD: игроки, очки,
                            игры, тесты)
    CloudSyncService.cs   — фасад синхронизации
    SyncService.cs        — оркестрация: push после игры, pull при входе
                            на новом устройстве

  —──────── UI/UX ─────────────────────────
    SettingsService.cs    — тема (светлая/тёмная), масштаб шрифта, звук
    SoundService.cs       — звуковые эффекты (генерация WAV на лету)
    HapticService.cs      — тактильная обратная связь
    NotificationService.cs— локальные уведомления (Plugin.LocalNotification)
    GameTutorialService.cs— оверлейные туториалы для каждой игры
    AchievementPopupService.cs — анимированный попап достижений
    AnimationExtensions.cs— Pop, FadeIn, Shake, Pulse
    DailyChallengeService.cs — ежедневное задание (seeded random)

  —──────── Контент ────────────────────────
    ContentLoader.cs      — загрузка JSON из Resources/Raw/games/
    TestBank.cs           — 5 тестов по 10 вопросов (486 строк)
    LeaderboardService.cs — таблица лидеров (облако + локальный fallback)

  2.3. Pages/ — Пользовательский интерфейс (35+ файлов)
  ──────────────────────────────────────────────────────
    GameBasePage.cs       — абстрактный базовый класс для всех игр
    GameCatalog.cs        — реестр всех 14 игр с метаданными
    ThemeColors.cs        — цвета темы (светлая/тёмная)

    — 14 игр в Pages/Games/ (см. раздел 5)
    — 5 IQ-тестов в TestSessionPage.cs (см. раздел 6)
    — UI-страницы: WelcomePage, LoginPage, RegisterPage, TrainingPage,
      GamesPage, TestsPage, StatsPage, ProfilePage, SettingsPage,
      StorePage, LeaderboardPage, AchievementsPage, AvatarPickerPage,
      ChangePasswordPage, SessionLockPage, OnboardingPage


3. БАЗА ДАННЫХ (SQLite)
--------------------------------------------------------------------------------
4 таблицы в файле cogniboost.db:

  Users (UsernameKey TEXT PK, DisplayName, Age, AvatarEmoji,
         PasswordHash, PasswordSalt, SkillsJson, Onboarded,
         PointsBalance, PointsLifetime, StreakLastDate,
         StreakCurrent, StreakLongest, UnlockedGamesJson,
         AchievementsJson)

  GameHistory (Id INTEGER PK AUTO, UsernameKey, GameId, GameTitle,
               Skill INT, Score, MaxScore, EarnedPoints, PlayedAtUtc)

  TestHistory (Id INTEGER PK AUTO, UsernameKey, TestId, TestTitle,
               CorrectAnswers, TotalQuestions, IqScore,
               EarnedPoints, PlayedAtUtc)

  Settings (Key TEXT PK, Value TEXT)

Миграция: при первом запуске данные переносятся из Preferences (старая
версия). Поддерживается до 200 записей истории на пользователя.


4. ЖИЗНЕННЫЙ ЦИКЛ ПРИЛОЖЕНИЯ
--------------------------------------------------------------------------------
  1) Запуск → сплеш-скрин (ActivityIndicator + "Загрузка...")
  2) Инициализация DatabaseService → создание/миграция БД
  3) Инициализация SettingsService → загрузка темы, шрифта
  4) Выбор корневой страницы:
       ┌──────────────────────────────────────────────┐
       │ Гостевой режим?            ───→ AppShell     │
       │ Авторизован?               ───→ AppShell     │
       │ Не авторизован + гостя нет ───→ WelcomePage  │
       │ Онбординг не пройден       ───→ Onboarding   │
       │                            Page              │
       └──────────────────────────────────────────────┘
  5) AppShell: TabBar с 5 вкладками
       ┌────┬─────┬─────┬──────┬──────┐
       │Глав│Игры │Тесты│Стат-ка│Профиль│
       └────┴─────┴─────┴──────┴──────┘

  6) При бездействии >30 мин на фоне → SessionLockPage
     (требуется повторный ввод пароля)


5. МИНИ-ИГРЫ (14 штук)
--------------------------------------------------------------------------------
Распределены по 4 когнитивным навыкам:

  — ПАМЯТЬ (Memory) ───────────────────────
  Найди пары         — классический мемори, 6 пар эмодзи
  Цветовая память    — повтори последовательность цветов (растёт с уровнем)
  Запомни число      — запомни и введи число (от 4 до 12 цифр)
  Повтори ряд        — Simon Says: 4 кнопки, последовательность растёт

  — ВНИМАНИЕ (Focus) ──────────────────────
  Быстрая реакция    — 12 раундов: зелёный = тап, красный = игнор
  Найди изменение    — запомни список → найди новое слово
  Истинный цвет      — Stroop-тест: выбери цвет шрифта, а не слово

  — ЛОГИКА (Logic) ────────────────────────
  Числовой ряд       — найди следующее число в прогрессии
  Матрица            — аналогии A:B = C:?
  Судоку-мини        — сетка 4×4 без повторов
  Весы               — транзитивные задачи на взвешивание

  — ЯЗЫК (Language) ───────────────────────
  Лишнее слово       — 4 слова, одно лишнее по смыслу
  Цепочка слов       — ассоциативная цепочка
  Анаграммы          — собери слово из перепутанных букв

Каждая игра — наследник GameBasePage. По завершении вызывается
FinishAsync(score, maxScore) — стандартный пайплайн:
  Сохранение результата → StreakService → AchievementsService →
  → попап новых достижений → фоновая синхронизация → GameResultPage.

★ Стартовые игры доступны сразу, остальные — за баллы (300–400 очков).


6. IQ-ТЕСТЫ (5 штук)
--------------------------------------------------------------------------------
  — Тест IQ (общий)
  — Тест памяти
  — Тест внимания
  — Тест логики
  — Числовой тест

Каждый тест: 10 вопросов, таймер 30 с на вопрос.
Формула IQ: 70 + (правильные / всего) × 60 → диапазон 70–130.
Результат сохраняется, начисляются баллы, проверяются достижения.


7. СИСТЕМА БАЛЛОВ
--------------------------------------------------------------------------------
Начисление за игру (AwardForResult):
  < 30% точности     →  1 балл (утешительный)
  30–70%             →  3 балла
  70–90%             →  5 баллов
  >= 90%             → 10 баллов

Ежедневное задание: удвоение баллов за указанную игру.
Стрики: +1 балл за каждый день серии.

Потратить баллы можно в магазине — покупка заблокированных игр.


8. ДОСТИЖЕНИЯ (24 штуки)
--------------------------------------------------------------------------------
Категории:
  Игровые     — первый шаг, 5/10 игр, 100% точность, 90% ×3 (5 шт.)
  Тестовые    — первый тест, IQ 100/120/130, 5 тестов (5 шт.)
  Прогресс    — мозг 200/500/800 очков (3 шт.)
  Баллы       — 500/1000 баллов (2 шт.)
  Стрики      — 3/7/30 дней (3 шт.)
  Навыки      — каждый навык до 500 (4 шт.)
  Разблокировка— купить игру / все игры (2 шт.)

Проверка: после каждого прохождения игры через AchievementsService.


9. ОБЛАЧНАЯ СИНХРОНИЗАЦИЯ
--------------------------------------------------------------------------------
Supabase (PostgreSQL + REST API).

  Push — после каждой игры:
    1) UpsertPlayerAsync   — профиль
    2) UpsertScoresAsync   — баллы по навыкам
    3) UpsertGameScoresAsync — история игр

  Pull — при входе на новом устройстве:
    1) FetchPlayerAsync    — поиск по username
    2) Создание локального аккаунта
    3) RestoreProfileAsync — аватар
    4) RestoreScoresAsync  — баллы
    5) RestoreGameHistoryAsync — история игр
    6) RestoreTestResultsAsync — тесты

Если облако не настроено — приложение работает полностью офлайн.

13. ОБОСНОВАНИЕ ВЫБОРА ТЕХНОЛОГИЙ
-------------------------------------------------------------------------------

   13.1. .NET MAUI (кросс-платформенный фреймворк)
   ───────────────────────────────────────────────────────────────────────
   Выбран как современная замена Xamarin.Forms. Позволяет писать
   единый код UI (XAML) и бизнес-логики (C#) для Android, iOS и Windows
   без дублирования. Встроенная Shell-навигация, AppThemeBinding для
   тёмной/светлой темы, маппинг ресурсов (шрифты, изображения, иконки)
   — всё это сократило объём кода на ~40% по сравнению с раздельной
   разработкой под каждую платформу.

   Альтернативы (Flutter, React Native) требуют изучения отдельного
   языка (Dart, JS/TS) и не дают прямого доступа к нативным API
   платформы без мостов. .NET MAUI использует знакомый по курсу язык
   C# и экосистему .NET.

   13.2. C# 13 (.NET 10)
   ───────────────────────────────────────────────────────────────────────
   Выбран как основной язык по следующим причинам:
     - Primary constructors — сократили шаблонный код моделей
     - Collection expressions — читаемая инициализация списков
     - Null-безопасность (Nullable enable) — предотвращение
       NullReferenceException на этапе компиляции
     - Source Generators (MauiXamlInflator) — компиляция XAML
       в C# на этапе сборки, ускорение Cold Start на 20–30%
     - Async/await — естественная модель для UI-приложений
       (неблокирующие операции с БД и сетью)

   13.3. SQLite + sqlite-net-pcl (локальная БД)
   ───────────────────────────────────────────────────────────────────────
   Выбор обоснован:
     - Не требует сервера — файловая БД, встроенная в приложение
     - Полная офлайн-работа — приложение функционирует без интернета
     - sqlite-net-pcl — ORM без SQL-запросов (CRUD через LINQ)
     - SharedCache — корректная работа при фоновой синхронизации
     - Миграция из Preferences — обратная совместимость с первой
       версией приложения, где данные хранились плоским ключ-значением

   Альтернативы (Realm, LiteDB) имеют меньшую популярность в .NET-
   сообществе и хуже документированы для MAUI.

   13.4. Supabase (облачное хранение)
   ───────────────────────────────────────────────────────────────────────
   Выбран как open-source альтернатива Firebase:
     - PostgreSQL — реляционная модель, согласованная с локальной SQLite
     - REST API — прямые HTTP-запросы без SDK (минимальные зависимости)
     - Row-Level Security — каждый пользователь видит только свои данные
     - Бесплатный тариф — достаточно для курсовой работы
     - Offline-first — приложение полностью работает локально,
       облако используется только для синхронизации между устройствами

   Firebase отвергнут из-за проприетарной лицензии и привязки
   к экосистеме Google.

   13.5. Plugin.LocalNotification (уведомления)
   ───────────────────────────────────────────────────────────────────────
   Выбор обусловлен:
     - Простая настройка — 3 строки кода для создания напоминания
     - Поддержка всех целевых платформ (Android, iOS, Windows)
     - Повторяющиеся уведомления — ежедневное напоминание
       о тренировке без дополнительного кода

   13.6. Архитектурный паттерн (Facade + Static Services)
   ───────────────────────────────────────────────────────────────────────
   В отличие от классического MVVM с DI-контейнером, выбрана
   упрощённая архитектура:
     - Static-сервисы — не требуют инъекции зависимостей,
       доступны из любой точки приложения
     - Facade (AccountStore) — единая точка входа для авторизации
       и профиля, изолирует изменения внутренних сервисов
     - Асинхронная инициализация — DatabaseService инициализируется
       при старте без блокировки UI (SemaphoreSlim)

   Это оправдано размером проекта: 35 страниц, 24 сервиса.
   Полноценный DI-контейнер (Microsoft.Extensions.DependencyInjection)
   добавил бы сложности без существенной выгоды для курсовой работы.

   13.7. SHA-256 + соль (безопасность паролей)
   ───────────────────────────────────────────────────────────────────────
   Пароли не хранятся в открытом виде:
     - SHA-256 — криптостойкое хеширование (необратимо)
     - Соль 32 байта — уникальна для каждого пользователя,
       защита от радужных таблиц
     - Миграция старых записей — автоматический пересчёт хеша
       при первом входе (обратная совместимость)

   Итог: выбранные технологии обеспечивают баланс между
   функциональностью, производительностью и объёмом кода,
   что критично для курсовой работы с ограниченными сроками.
